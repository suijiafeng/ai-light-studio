# 二次开发指南

面向后续接手开发的工程师，说明架构设计、代码地图与常见扩展做法。

## 1. 整体架构

```
浏览器 (Vue3 SPA)
   │  /api/** (JWT 或 X-API-Key)
   ▼
Express 后端 ──┬── SQLite（用户/生成记录/订单/流水/密钥）
               ├── 本地磁盘（uploads 源图 / results 结果图）
               ├── AI服务层 services/ai.js（mock本地出图 ⇄ Replicate IC-Light）
               ├── 支付层 services/wechatpay.js（mock沙箱 ⇄ 微信V3）
               └── 邮件层 services/mailer.js（开发模式 ⇄ SMTP）
```

设计原则：**所有外部依赖（AI/支付/邮件/数据库驱动）都有零配置的本地降级实现**，保证任何环境克隆下来即可完整跑通，填入密钥即切换真实服务。

## 3. 数据库表结构

```sql
users(id, email, password_hash, nickname, role, credits,
      member_expires_at, last_daily_at, invite_code, invited_by, banned, created_at)
generations(id, user_id, source_path, result_path, params(JSON), status,
      error, cost, batch_id, share_id, created_at, finished_at)
orders(id, user_id, package_id, title, amount(分), credits, member_days,
      status[pending|paid|closed], pay_method, transaction_id, created_at, paid_at)
credit_logs(id, user_id, change, balance, type[register|daily|invite|recharge|consume|refund], remark, created_at)
email_codes(id, email, code, purpose[register|reset], expires_at, used, created_at)
api_keys(id, user_id, key, name, revoked, created_at)
```

改表规范：在 `db.js` 底部的增量ALTER数组里追加语句（try/catch包裹），老库启动时自动迁移。

## 4. 常见扩展怎么做

### 4.1 新增一种灯光风格

1. `server/src/services/ai.js` 的 `STYLE_PRESETS` 加一项（name/temp/brightness/saturation/prompt）
2. 前端 `StudioView.vue`、`HistoryView.vue`、`SharePage.vue`、`ReportView.vue` 中的 `styleNames/STYLE_NAMES` 映射加中文名
3. 连拍会自动包含新风格（遍历STYLE_PRESETS），注意连拍算力 `MULTI_COST` 是否要调整

### 4.2 更换/新增AI服务商

只改 `services/ai.js`：仿照 `replicateRelight` 写 `xxxRelight(sourcePath, params, outPath)`，在 `relight()` 里按 `config.ai.provider` 分发。约定：函数负责把结果写到 outPath，水印/尺寸由 `finalizeImage` 统一处理，不要在服务商函数里做。

### 4.3 新增充值套餐

`server/src/config.js` 的 `packages` 数组加一项即可（type: credits|member，price单位分）。前端自动渲染。

### 4.4 新增一个页面

1. `web/src/views/XxxView.vue`
2. `router/index.js` 注册路由（meta.auth 控制登录，meta.admin 控制管理员）
3. 需要接口就在 `api/index.js` 加函数、后端 `routes/` 加路由

### 4.5 SQLite 迁移 MySQL

重写 `db.js`：用 mysql2 实现 `prepare().get/all/run` 与 `transaction()` 同名接口（业务代码全部经由这几个方法，无需改动）。注意 AUTOINCREMENT 差异不存在（主键全部是应用层UUID），JSON字段用TEXT即可。

### 4.6 接入内容审核（国内上线必须）

在两处挂钩子：`routes/generate.js` 上传成功后（审源图）、`startJob` 的成功回调里（审结果图）。推荐阿里云绿网/腾讯云CMS，违规则置 status=failed 并退算力。

### 4.7 图片迁移OSS

封装 `services/storage.js` 提供 `save(buffer, key)` / `url(key)`，替换 generate.js 里的 multer diskStorage 与静态 `/uploads` `/results` 路由；数据库字段存key不变。

## 5. 约定与规范

- 接口返回一律 `{ code, msg, data }`；错误码 401/403/429/400/500 语义固定，前端拦截器依赖它
- 算力变更必须走 `changeCredits`（事务+流水），禁止直接UPDATE users.credits
- 金额一律用"分"存储整型，展示层再除100
- 用户可见文案全部中文，代码注释中文
- 前端接口调用只能经 `api/index.js`，禁止在组件里直接axios

## 6. 单元测试

- 框架：Vitest + Supertest，测试文件在 `server/tests/`，`npm test` 运行
- 隔离：`tests/setup.js` 为每个测试文件创建独立临时数据库并关闭限流（`RATE_LIMIT_DISABLED=1`），不会污染真实数据
- 结构：`app.js` 导出Express实例（供supertest），`index.js` 仅负责监听——新增路由记得挂到 app.js
- 约定：新增接口必须补对应测试；提交前 `npm test` 全绿
- 复用：`tests/helpers.js` 提供 register / uploadImage / waitGeneration 等工具函数

## 7. 本地调试技巧

- 后端热重载：`npm run dev`（node --watch）
- 邮件验证码：不配SMTP时验证码打印在后端控制台且随接口返回（devCode）
- 模拟支付：充值弹窗内置"模拟支付成功"按钮（PAY_PROVIDER=mock时）
- 想快速造数据：注册多账号+管理后台调整算力即可

## 9. 已知注意事项

- `web/dist` 为构建产物，改完源码需重新 `npm run build` 才会反映到生产模式（开发用 `npm run dev` 实时生效）
- 后端接口测试共42例、前端组件测试15例、E2E冒烟1条完整链路；任何接口改动务必先跑 `npm test`
