# 部署运维手册

从零到正式上线的完整操作手册，适用于购买云服务器后独立部署。

## 1. 服务器选型建议

| 规模 | 配置 | 说明 |
|---|---|---|
| 起步（日活<500） | 2核4G · 40G系统盘 · 3-5M带宽 | mock模式或Replicate外部出图，图片走本机磁盘 |
| 成长（日活500-5000） | 4核8G · 数据盘100G+ | 建议图片迁OSS+CDN，数据库迁MySQL |
| 备案 | 国内服务器必须ICP备案 | 微信支付要求已备案域名 |

操作系统建议 Ubuntu 22.04 LTS。

## 2. 环境安装

```bash
# Node.js 20 LTS（NodeSource源）
curl -fsSL https://deb.nodesource.com/setup_20.x | sudo -E bash -
sudo apt-get install -y nodejs git nginx

# 进程守护
sudo npm i -g pm2
```

## 3. 部署步骤

### 方式一：宿主机 pm2 部署

```bash
# 1) 上传代码（git或scp均可）
cd /opt && git clone <你的仓库> ai-light-studio && cd ai-light-studio

# 2) 后端
cd server
cp .env.example .env && vim .env      # 见下方生产配置清单
npm install --omit=dev

# 3) 前端打包（后端会自动托管 web/dist）
cd ../web && npm install && npm run build

# 4) pm2 启动并开机自启
cd ../server
pm2 start src/index.js --name ai-light
pm2 save && pm2 startup
```

### 生产环境 .env 必改项

```
JWT_SECRET=<openssl rand -hex 32 生成>
ADMIN_EMAILS=你的管理员邮箱
AI_PROVIDER=replicate          # 及 REPLICATE_API_TOKEN / REPLICATE_MODEL_VERSION
PAY_PROVIDER=wechat            # 及 WXPAY_* 五项 + 证书文件放 server/cert/
WXPAY_NOTIFY_URL=https://你的域名/api/pay/notify
SMTP_HOST/PORT/USER/PASS       # 邮件验证码
EMAIL_VERIFY=on                # 上线建议开启，防批量注册薅免费算力
```

### 方式二：Docker 部署（推荐，免装Node环境）

项目根目录已提供 `Dockerfile`、`docker-compose.yml`、`.dockerignore`，服务器只需安装 Docker：

```bash
# 1) 上传代码
cd /opt && git clone <你的仓库> ai-light-studio && cd ai-light-studio

# 2) 准备配置（同上方 .env 必改项）
cp server/.env.example server/.env && vim server/.env

# 3) 构建并启动（多阶段构建：自动打包前端、安装后端依赖）
docker compose up -d --build

# 4) 验证
curl http://localhost:3000/api/health
```

要点说明：

- **数据持久化**：SQLite数据库、上传图、结果图都在命名卷 `app-data` 中，`docker compose down` 不会丢数据。备份命令：
  ```bash
  docker run --rm -v ai-light-studio_app-data:/data -v /backup:/backup alpine \
    tar czf /backup/ai-light-$(date +%F).tar.gz -C /data .
  ```
- **配置注入**：`server/.env` 不打进镜像（已在 `.dockerignore` 排除），由 compose 的 `env_file` 在启动时注入，改配置后 `docker compose up -d` 即可生效。
- **微信支付证书**：`PAY_PROVIDER=wechat` 时把证书放 `server/cert/`，并取消 compose 中证书挂载行的注释。
- **升级版本**：`git pull && docker compose up -d --build`，旧容器自动替换。
- **日志**：`docker compose logs -f`；容器自带健康检查（`/api/health`，30秒一次），`docker ps` 可看到 healthy 状态。
- Nginx 反代配置与非Docker部署完全一致（见下一节），继续指向 `127.0.0.1:3000`。

## 4. Nginx + HTTPS

```bash
# 证书（Let's Encrypt 免费）
sudo apt install -y certbot python3-certbot-nginx
sudo certbot --nginx -d your-domain.com
```

```nginx
server {
    listen 443 ssl http2;
    server_name your-domain.com;
    ssl_certificate     /etc/letsencrypt/live/your-domain.com/fullchain.pem;
    ssl_certificate_key /etc/letsencrypt/live/your-domain.com/privkey.pem;

    client_max_body_size 20m;              # 上传图片上限

    location / {
        proxy_pass http://127.0.0.1:3000;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_read_timeout 300s;            # AI生成耗时较长
    }
    # 结果图缓存，减轻回源
    location ~ ^/(results|uploads)/ {
        proxy_pass http://127.0.0.1:3000;
        proxy_cache_valid 200 7d;
        expires 7d;
    }
}
server { listen 80; server_name your-domain.com; return 301 https://$host$request_uri; }
```

## 5. 日常运维

```bash
pm2 logs ai-light          # 查看日志
pm2 restart ai-light       # 重启
pm2 monit                  # 资源监控
```

### 数据备份（务必配置）

所有数据都在 `server/data/`（SQLite数据库 + 上传图 + 结果图）。每日凌晨自动备份：

```bash
crontab -e
# 每天3点备份到 /backup，保留7天
0 3 * * * tar czf /backup/als-$(date +\%F).tar.gz /opt/ai-light-studio/server/data && find /backup -mtime +7 -delete
```

建议再同步一份到对象存储：`ossutil cp -r /backup oss://your-bucket/backup/`

### 版本升级流程

```bash
cd /opt/ai-light-studio && git pull
cd web && npm install && npm run build
cd ../server && npm install --omit=dev
pm2 restart ai-light
```

数据库结构变更由代码启动时自动执行（`db.js` 中的增量ALTER），无需手工迁移。

## 6. 安全加固清单

- [ ] `JWT_SECRET` 使用32位以上随机串，泄露立即更换（会使全员登录失效）
- [ ] 服务器安全组只开放 80/443/22，3000端口不对公网开放
- [ ] SSH改用密钥登录，禁用密码
- [ ] `EMAIL_VERIFY=on` 防脚本批量注册
- [ ] 微信商户私钥 `apiclient_key.pem` 权限设为600，不入git
- [ ] 定期 `npm audit` 检查依赖漏洞
- [ ] 上线前删除测试账号，数据库文件权限600

## 7. 监控告警（可选）

- 简单方案：`pm2 install pm2-logrotate` 日志轮转 + 云厂商自带的CPU/内存/磁盘告警
- 拨测：用云监控每分钟请求 `https://域名/api/health`，非200告警
- 业务指标：管理后台"数据总览"每日巡检生成成功率，失败率>5%需排查AI接口余额/网络

## 8. 扩容路线（用户量上来之后）

1. **图片上OSS/COS + CDN**：改 `server/src/routes/generate.js` 存储层，上传/结果写对象存储，数据库仅存URL
2. **SQLite → MySQL**：仅需重写 `server/src/db.js`（表结构见二次开发指南），业务SQL基本通用
3. **生成队列**：进程内异步改 Redis + BullMQ，支持横向扩容多个worker、重启不丢任务
4. **多实例负载均衡**：Nginx upstream 挂多台后端，session无状态（JWT）天然支持
